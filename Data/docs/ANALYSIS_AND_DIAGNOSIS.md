# AI问数 — 企业级销售经管数据管理平台：功能分析、问题诊断与实现方案

> 本文档对应面试任务中的 **1. 功能分析**、**2. 问题诊断** 与 **3. 功能实现架构说明**。原型文件 `Data/index.html` 保持原样未做任何修改。

---

## 一、功能分析（模块职责与交互逻辑）

通过对原型 `Data/index.html`（共 4,594 行）的全面梳理，平台围绕**“企业级销售经管数据问答（Text2SQL + 智能分析 + 可视化）”**构建，包含 **4 个前端核心页面模块** 与 **底层经管数据底座**：

### 1. 智能问数模块（`#page-ai-qa`）
这是平台的核心工作台，负责自然语言提问、多轮上下文会话、透明化分析过程展示及图表呈现：
- **会话管理侧边栏（`#qaSidebar`）**：
  - 展示近 30 天问答会话列表，支持**开启新对话**、**会话置顶/取消置顶**、**重命名**、**删除会话**以及侧边栏折叠状态记忆。
- **欢迎引导区（`#qaWelcomeView`）**：
  - 新建会话或空会话时展示可配置的**开场白文案**与**“你可以这么问我”快捷提问卡片**，点击卡片可直接发起提问。
- **多轮问答对话区（`#qaChatView`）**：
  - **用户消息气泡**：支持单条问题的**收藏/取消收藏**（与底部快捷提问面板联动）、**原地编辑并重新发送**、**重新生成回答**、**一键复制**。
  - **AI 结构化分析卡片（`.qa-ai-card`）**：
    - **分析过程折叠面板（`.aa-wrap`）**：按 5 个标准阶段透明化展示 Text2SQL 全链路：① 选择数据表&数据时效 $\rightarrow$ ② 推理逻辑 $\rightarrow$ ③ 执行取数 SQL $\rightarrow$ ④ 展示取数结果 $\rightarrow$ ⑤ 执行结束。
    - **模块 1 - 数据发现**：提炼核心业务结论与关键指标汇总。
    - **模块 2 - 数据表格**：以结构化表格展示 SQL 查询返回的明细或聚合结果。
    - **模块 3 - 数据统计**：展示记录总数、平均值、最大值、最小值等统计特征。
    - **模块 4 - 数据可视化**：根据数据结构绘制柱状对比图、饼图/环形图、折线趋势图或水平条形图。
    - **卡片页脚与追问建议**：提供复制、不满意报错反馈（触发 `#optimizeModal` 提交至回复校对队列）、语音播报（TTS）、耗时与 Token 统计，以及 3 条延伸追问建议 Chip。
- **底部输入栏与快捷提问浮层（`.qa-input-bar`）**：
  - 左侧闪电按钮唤起**快捷提问面板（`#qqPanel`）**，包含**「常问」**（高频问题自动聚合）与**「收藏」**（用户星标问题）两个标签页；右侧支持语音输入（STT）与发送。
- **数据源选择器（`#qaFilePickerModal`）与问答日志（`#qaLogView`）**：
  - 支持勾选参与问答检索的台账与统计报表范围；支持按时间跨度、用户类型、标题关键词检索问答日志，并在右侧滑出**会话详情抽屉（`#qaDetailPanel`）**回溯完整上下文与调用的 LLM 模型。

### 2. 系统管理 - 应用配置模块（`#page-sys-app`）
管理 AI 问数工作台的 6 项全局交互开关与参数配置：
1. **对话开场白**：控制欢迎语及推荐问题显隐，弹窗支持自定义开场白文本及最多 10 条开场问题。
2. **下一步问题建议**：控制 AI 回复卡片下方是否自动生成 3 条延伸追问提示条。
3. **文字转语音（TTS）**：控制 AI 回复卡片是否开放语音播报能力。
4. **语音转文字（STT）**：控制输入框是否开放麦克风语音提问能力。
5. **模型配置**：控制自定义模型路由开关，并提供模型配置页快捷入口。
6. **常问设置**：控制快捷提问面板中的「常问」推荐开关，支持自定义“问题频次阈值（`hotThreshold`）”。

### 3. 系统管理 - 模型配置模块（`#page-sys-model`）
- 管理智能问数底层调用的 LLM 模型（预置 `GPT-4o`、`GPT-4o-mini`、`Claude 3.5 Sonnet`、`DeepSeek-V3`、`Qwen2.5-72B`、`GLM-4-Plus`、`Moonshot-v1`）。
- 支持通过弹窗新增自定义 OpenAI 兼容模型（配置 `Base URL`、`API Key`、`Model Name`），要求先通过**「测试连接」**校验可用性后方可保存。

### 4. 反馈管理 - 回复校对模块（`#page-sys-feedback-user`）
- 承接用户在问答界面点击“反馈 $\rightarrow$ 数据有误”提交的异常记录，形成数据治理闭环。
- 支持按问题关键词、反馈用户、处理状态（`待处理` / `已处理`）组合筛选与分页。
- 点击「处理」打开校对弹窗（`#feedbackRemarkModal`），左侧对照展示**用户原始提问**与**AI 原始回复及 SQL**，右侧由管理员更新处理状态并填写校对备注。

## 二、问题诊断（原型存在的缺陷与不合理之处）

对 `Data/index.html` 进行代码审查与交互走查后，诊断出以下 **8 类核心问题**：

| 序号 | 问题类别 | 具体代码位置 | 现象与根因分析 | 修复与实现方案 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **AI 问答与 SQL 完全硬编码（假数据）** | `renderAaSteps` (`L2655`)、`genAiReply` (`L2692`) | 无论用户输入什么自然语言问题，永远返回写死的“2026年各经营单元商业目标 TOP5”静态表格、固定 SQL 与固定柱状图，未连接真实数据库与 Text2SQL 引擎。 | 后端构建真实 SQLite 销售经管数据库（含 8 张核心表）与 **LLM + 语义规则双引擎 Text2SQL**，实时解析任意提问、执行真实 SQL、动态生成统计结论与多类型图表。 |
| 2 | **DOM 空指针异常隐患** | `navigateTo` (`L1984`) $\rightarrow$ `updateQaSourceCount` (`L2284`) | `updateQaSourceCount()` 直接设置 `document.getElementById('qaSourceIndicator').textContent`，但 HTML 中 `#qaSourceIndicator` 已被误删，调用即抛出 `TypeError: Cannot set properties of null`。 | 在智能问数顶部操作栏补全 `#qaSourceIndicator` 数据源选择按钮与状态展示，并消除空指针风险。 |
| 3 | **隐藏功能入口断联（数据源选择 & 问答日志）** | `.qa-rh-right` (`L887`)、`#qaLogView` (`L923`)、`#qaFilePickerModal` (`L4492`) | 原型中完整编写了问答日志视图 `#qaLogView`、详情抽屉 `#qaDetailPanel` 以及数据源选择弹窗 `#qaFilePickerModal` 的 HTML 与 JS 函数（`switchQaTab('log')`、`toggleFilePicker()`），但顶栏 `.qa-rh-right` 被清空，导致用户无法进入这两个模块。 | 在智能问数顶部栏右侧恢复**「数据源选择」**与**「问答日志」**入口按钮，打通数据源过滤与日志审计抽屉全流程。 |
| 4 | **应用配置开关与问答界面脱节（配置不生效）** | `genAiReply` (`L2730-L2732`)、`qa-mic-btn` (`L908`)、`_QQ_DATA.recent` (`L2467`) | ① 关闭「下一步问题建议」后，AI 回复依然渲染 `.qa-followup`；<br>② 「常问设置」阈值 `hotThreshold` 从未参与统计，常问列表写死为 2 条固定文本；<br>③ TTS 与 STT 开关不控制语音按钮显隐，且按钮 `onclick=""` 为空实现；<br>④ 问答日志详情抽屉中的模型名称固定写死为 `GPT-4o` (`L4485`)。 | 将 `appConfig` 全量接入前后端状态：动态控制开场白、延伸追问、TTS/STT 按钮显隐及 Web Speech API 语音能力；基于真实提问频次与 `hotThreshold` 动态计算「常问」列表；日志详情真实记录并展示当时调用的模型名称。 |
| 5 | **反馈校对丢失 AI 回复上下文** | `submitDataError` (`L2601-L2604`) | 用户点击报错反馈时，`submitDataError()` 写入的 `aiReply` 固定为空字符串 `''`，导致管理员在「回复校对」弹窗中永远只能看到 `（暂无AI回复数据）`，无法核查到底哪里数据有误。 | 提交反馈时，自动抓取当前 AI 卡片的完整结论摘要、执行的 SQL 语句及统计指标一并提交至后端数据库，并在反馈弹窗支持用户补充具体错误描述。 |
| 6 | **消息编辑与取消编辑存在状态 Bug** | `qaEditMsg` (`L2740`)、`qaCancelEdit` (`L2760`)、`qaResend` (`L2771`) | ① `qaCancelEdit` 读取 `ta.getAttribute('data-orig')`，但 `qaEditMsg` 创建 `<textarea>` 时根本未设置 `data-orig` 属性，导致取消编辑时文本恢复异常；<br>② 编辑历史消息重新发送时，仅删除了 DOM 中最后一个 `.qa-ai-msg`，且未更新 `_qaSessions` 持久化数组，刷新页面后旧消息依然存在。 | React 状态化管理消息列表：编辑任意轮次用户消息并重发时，自动截断该消息之后的历史分支、同步更新后端数据库并重新生成 AI 回答；取消编辑准确还原原始文本。 |
| 7 | **XSS 注入与字符串转义脆弱性** | `sendChat` (`L2630`)、`loadQaSession` (`L2377`) | 原型大量使用 `innerHTML +=` 拼接用户输入，且仅用 `.replace(/'/g, "\\'")` 处理内联 `onclick` 参数，若用户提问包含双引号、尖括号或换行符，极易破坏 DOM 结构甚至引发 XSS。 | 采用 React JSX 安全渲染与事件绑定机制，彻底杜绝拼接 `innerHTML` 导致的 DOM 破坏与 XSS 风险。 |
| 8 | **大量未使用的冗余死代码与未闭合标签** | `L1318-L1323`、`L1346-L2160`、`L3001-L4267` | HTML 第 1318 行残留了未闭合的 `<div class="modal-footer">`（属于被删掉的 `acctDeleteDialog`）；JS 中残留了约 2,500 行已删除页面（驾驶舱、5 张报表、账号权限树）的冗余代码，但其中蕴含了宝贵的业务表结构定义。 | 前端采用模块化 React 组件重构，彻底清理死代码；同时将原冗余 JS 中的**三大台账 + 五大报表数据模型**提炼转化为后端 SQLite 数据库的真实业务表与种子数据。 |
